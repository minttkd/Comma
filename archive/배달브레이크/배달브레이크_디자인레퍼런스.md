# 배달브레이크 디자인 레퍼런스

유사 서비스의 UI/UX를 두 갈래로 찾아봤다. 하나는 "결제 직전에 개입해서 멈추게 하는" 충동구매 방지 앱들이고, 다른 하나는 "카테고리별 예산 한도를 설정하고 초과를 경고하는" 가계부 앱들이다. 배달브레이크 v2는 이 두 가지를 합친 형태라서, 각각에서 가져올 점을 따로 정리했다.

---

## 1. 결제 직전 개입(Intervention) 레퍼런스

배달브레이크의 핵심 UX — "결제 버튼을 누르는 순간 멈추게 하기" — 와 가장 가까운 컨셉의 앱들이다.

### Second Thoughts
스스로를 예산 앱이 아니라 "행동 차단기(behavioural circuit breaker)"로 소개한다. 지출 내역을 보여주는 대신 지출 전에 멈추고 결정하게 만드는 것이 핵심 컨셉. 사지 않기로 한 항목을 몇 초 안에 기록하고, 아낀 금액 누적·연속 기록(streak)·업적으로 긍정 피드백을 준다.
→ **적용점**: 배달브레이크의 "방지 실적" 화면에 streak(연속 방지 일수)나 업적 뱃지 같은 긍정 피드백 요소를 추가하면 동기부여가 강해진다.
[Second Thoughts](https://mwm.ai/apps/second-thoughts/6756847420)

### Skip & Save
지출 결정을 기록하고 아낀 금액을 모으는 컨셉의 앱.
[Skip & Save](https://mwm.ai/apps/skip-save/6781008496)

### Piggy Pause
충동이 들 때 직접 앱을 켜서, 돼지 캐릭터를 탭하면 **20초 호흡 애니메이션**으로 결정을 늦추고, 그 다음에야 행동(포기/진행) 버튼이 나온다. 주간 리캡에서 참은 횟수·아낀 금액을 요약해 보여준다.
→ **적용점**: 배달브레이크 오버레이가 AI 문답으로 바로 넘어가기 전에, 3~5초 정도의 짧은 "숨 고르기" 애니메이션을 넣으면 "즉흥적으로 닫기" 비율을 줄일 수 있다. 지금 구조(모달 바텀시트)에 큰 변경 없이 추가 가능.
[Piggy Pause](https://mwm.ai/apps/piggy-pause/6782881616)

### Buy Pause
상품명·가격·구매 이유(3~5개)를 적고 "최종 결정일"까지 기다리게 하는 방식. 결정일에 욕구 변화 그래프와 함께 "Buy / Skip for now"를 고른다.
→ **적용점**: 배달브레이크는 결제 직전 즉시 판단이라 "대기" 컨셉은 그대로 쓰기 어렵지만, AI 문답에서 "왜 이걸 지금 사려고 하나요?" 같은 이유를 짧게 선택하게 하면 Buy Pause의 "이유 기록" 느낌을 즉석 버전으로 가져올 수 있다.
[Buy Pause](https://mwm.ai/apps/buy-pause/6757339467)

### Impulse Blocker: Self-Control / Checkout Chill / Don't Buy That (크롬 확장)
웹 결제창을 가로채 경고를 띄우는 브라우저 확장들. 배달브레이크가 안드로이드 접근성 서비스로 하려는 것과 같은 "결제 시점 가로채기" 컨셉을 웹에서 구현한 선례로 참고할 만하다.
[Impulse Blocker: Self-Control](https://apps.apple.com/ae/app/impulse-blocker-self-control/id6748925784) · [Checkout Chill](https://chromewebstore.google.com/detail/bnadcnafliodbihnccncpehokdmjjeon) · [Don't Buy That](https://chromewebstore.google.com/detail/lenjjabdmimacdebddfplnafnlljghhd)

**이 섹션의 공통된 한계**: 위 앱들은 전부 "사용자가 직접 입력/대기"하는 방식이고, 배달브레이크처럼 결제 버튼 터치를 자동으로 감지해 즉시 개입하는 앱은 찾지 못했다. 즉 배달브레이크의 "자동 감지 + 즉시 개입" 방식 자체는 차별점으로 계속 강조할 만하다.

## 2. 가계부 한도 설정 & 초과 경고 레퍼런스

가계부 화면에서 카테고리별 한도를 어떻게 입력받고, 초과를 어떻게 보여주는지에 대한 참고.

### EveryDollar 예산 생성 플로우 (ScreensDesign 정리)
- 예산 생성을 여러 단계로 나누고 상단에 진행 표시줄을 둔다.
- 카테고리를 **카드로 묶고, 카드를 누르면 한도 입력 모달**이 뜨는 구조.
- 한도 입력 모달은 여러 행(입력 필드)을 세로로 나열하고 하단에 고정된 "저장" 버튼을 둔다.
- 화면 상단에 "남은 예산" 지표를 항상 띄워둔다.
- 경고 색상(빨강/주황 등)만으로 초과를 표시하지 않고, 반드시 라벨이나 숫자(%)를 같이 보여준다.
[budget app dashboard design (ScreensDesign)](https://screensdesign.com/articles/budget-app-dashboard-design/) · [creating budgets flow](https://screensdesign.com/explore/flows/creating-budgets/)

→ **적용점**: 지금 `linkAccountScreen`의 "고정 수입·지출" 카드 목록 구조를 그대로 재사용해서, 카테고리(배달/쇼핑) 카드를 추가하고 각 카드를 누르면 한도 입력 모달이 뜨는 식으로 확장하면 기존 UI 패턴과 잘 맞는다. 신호등 색상(`--safe`/`--expense`/`--danger`)은 이미 style.css에 있으니 그대로 쓰되, 숫자(예: "76,000 / 80,000원")를 항상 같이 보여주는 걸 원칙으로 하면 좋다.

### BDGT App
초보자를 겨냥해 밝고 부담 없는 톤(달러 지폐 배경, 친근한 색)을 쓰고, 기능을 최소화해 복잡함을 줄인 예산 앱. 카테고리별 월 예산과 가용 소득을 설정하고, 남은 예산이 적으면 알림을 보낸다.
[BDGT App (Behance)](https://www.behance.com/gallery/6119969/BDGT-App)

### 국내 가계부 앱: 토스, 뱅크샐러드, 모두의 가계부, 편한가계부
국내 사용자에게 더 익숙한 UI 톤을 참고하려면 아래 앱들이 적합하다. 특히 뱅크샐러드는 카테고리별 소비를 신호등(초록/노랑/빨강)처럼 보여주는 패턴이 있어 배달브레이크의 "예산·빈도 신호등 판단" 기능과 톤이 가장 비슷하다.
[뱅크샐러드](https://apps.apple.com/KR/app/id1195804784) · [모두의 가계부](https://apps.apple.com/kr/app/%EB%AA%A8%EB%91%90%EC%9D%98-%EA%B0%80%EA%B3%84%EB%B6%80-%EB%93%9C%EB%9E%98%EA%B7%B8-%ED%95%9C%EB%B2%88%EC%9C%BC%EB%A1%9C-%EC%9E%85%EB%A0%A5%ED%95%98%EB%8A%94-%EC%86%8C%EB%B9%84%EC%8A%B5%EA%B4%80/id6752123281) · [편한가계부](https://apps.apple.com/kr/app/%EA%B0%80%EA%B3%84%EB%B6%80-%EC%A7%80%EC%B6%9C-%EC%98%88%EC%82%B0-%EC%A0%88%EC%95%BD-%ED%8E%B8%ED%95%9C%EA%B0%80%EA%B3%84%EB%B6%80/id6445957924?l=ko)

## 3. 배달브레이크 v2에 바로 적용할 수 있는 제안

1. **가계부 한도 설정 화면**: 기존 `linkAccountScreen`의 카드 목록 패턴을 재사용해, "배달"·"쇼핑" 카테고리 카드를 추가하고 각 카드를 누르면 한도 입력 모달(EveryDollar 방식)이 뜨게 한다.
2. **개입 오버레이에 짧은 호흡/대기 요소 추가**: Piggy Pause처럼 AI 문답 전에 3~5초짜리 짧은 전환 애니메이션을 넣어 "반사적으로 닫기"를 줄인다. 기존 모달 바텀시트 구조를 그대로 두고 애니메이션만 얹으면 된다.
3. **초과 경고는 색상 + 숫자/퍼센트를 항상 같이**: 지금 `check-result.danger` 클래스처럼 색상은 있지만, "80,000원 중 99,000원 (124%)" 같은 구체적 숫자를 항상 같이 보여주는 걸 원칙으로 한다.
4. **방지 실적에 긍정 피드백 강화**: Second Thoughts처럼 연속 방지 일수(streak)나 "이번 달 가장 많이 참은 카테고리" 같은 요약을 추가하면 기존 `stats-box`를 크게 바꾸지 않고도 동기부여 요소를 더할 수 있다.
5. **차별점 유지**: 조사한 앱들은 대부분 사용자가 직접 입력·대기하는 방식이라, 배달브레이크처럼 결제 버튼을 자동 감지해 즉시 개입하는 방식은 흔치 않다. 발표나 기획서에서 이 부분을 계속 차별점으로 강조할 수 있다.
