## 문제 근거 (공개 통계 — 1차 조사 없음, 14주차 사용자 테스트로 검증)

- 1인 가구 804.5만(전체 36.1%), 소비지출 중 음식·숙박 18.2%로 2위 — 국가데이터처 「2025 통계로 보는 1인 가구」(2024 기준)
- 2026년 8월 음식서비스 온라인 거래액 3조 9,677억 원, 전년 동월 대비 +7.6%, 모바일 78.1% — 국가데이터처 온라인쇼핑동향(2026.10.1 발표)
- 배달 이용 시간대 밤 10~12시 26.2%(중복응답) — 엠브레인 트렌드모니터, 2019.2, 만 19~59세 1,000명
- 2030의 70.8%가 소비·지출 습관 개선 의향, 개선이 절실한 순간 1위 "충동구매로 인한 소비 내역이 예상보다 많을 때"(24.5%) — 핀크·대학내일20대연구소, 2018
- 인사이트: ① 가계부는 쓴 뒤에만 말한다 → 결제 버튼 순간 개입 ② 모든 소비에 끼어들면 앱을 지운다 → 한도 초과에만 ③ 막으면 우회한다 → 차단 대신 질문

## 시스템 아키텍처

- **Frontend — Android 앱(Java, minSdk 26)**: 화면 S01~S04·S09·S10(Activity), 접근성 서비스(GuardService: 결제 화면 감지, 결제 버튼 가드), 오버레이(S05~S08), 엔진(BudgetEngine, TriggerEngine, QuestionTemplates, ScreenParser, KeywordJudge), Room(SQLite). 예산·트리거·강도는 기기에서 계산.
- **Backend — Flask API(Python)**: AI 프록시(키 보관, 2초 타임아웃, 판정 캐시), Mock 오픈뱅킹, 기록 백업·월말 집계.
- **Database**: 앱 Room + 서버 DB(SQLite → PostgreSQL), 같은 9개 테이블.
- **외부**: Claude API(판정·질문 생성).

### API 명세 (초안)

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| POST | /api/v1/ai/judge | app, items[], amount | judgment(필요/애매/충동), is_food |
| POST | /api/v1/ai/question | triggers, intensity, index, facts(한도·여윳돈·식비 잔액), history_summary, answers[] | question, chips[2~3], q_type |
| POST | /api/v1/ai/summary | qa[] | summary(한 줄) |
| GET | /api/v1/bank/transactions?since= | — | transactions[](merchant, amount, occurred_at) |
| POST | /api/v1/records/sync | attempts[], interventions[], qa_turns[], reviews[] | ok, synced_at |
| GET | /api/v1/reports/monthly?month= | — | interventions, prevented, prevented_sum, mind_change_rate, late_count, regret_rate, next_food_budget |

인증: 기기 등록 시 받은 익명 device_token. AI에는 상품명·금액·답변을 데이터 필드로만 전달(프롬프트 인젝션 방어), 화면 원문은 보내지 않음.

### 데이터 흐름 (14단계)

동기화: ① 앱 실행 시 GET /bank/transactions(1시간 캐시) ② 기기에서 분류·여윳돈 갱신 → 결제 순간: ③ 결제 화면 이벤트 → 버튼 가드 ④ 결제 버튼 터치 → 최종 금액·상품명 재추출 ⑤ POST /ai/judge(쿠팡·무신사) ⑥⑦ Claude 판정 ⑧ 판정(2초 초과 시 키워드) ⑨ 예산 엔진 → 트리거 4종 → 강도 ⑩⑪ POST /ai/question → 질문+칩(지연 시 기본 질문) ⑫ 사용자 답·결정 → 기록·리포트: ⑬ POST /records/sync ⑭ 서버 저장·월별 집계

## ERD (9개 테이블)

| 테이블 | 주요 컬럼 | 관계 |
|---|---|---|
| USER | user_id PK, device_token, income_amount, pay_day, k_factor(2.0), late_night_rule, last_sync_at | — |
| FIXED_EXPENSE | id PK, user_id FK, category(월세·관리비/공과금/통신/교통/구독), amount | USER 1:N |
| FOOD_BUDGET | id PK, user_id FK, month, budget/actual(마트+쿠팡 식료품), calibrating | USER 1:N |
| BANK_TX | tx_id PK, user_id FK, occurred_at, merchant, amount, category(고정/식비/여윳돈) | USER 1:N |
| PAYMENT_ATTEMPT | attempt_id PK, user_id FK, app, title, amount, judgment, is_food, is_late_night, result(통과/식비/개입), created_at | USER 1:N |
| INTERVENTION | intervention_id PK, attempt_id FK, triggers, intensity, nth_of_day, outcome(방지/이유 선택/숙고 후/이탈), stopped_at_q, reason_chip, summary | ATTEMPT 1:0..1 |
| QA_TURN | turn_id PK, intervention_id FK, seq(1~3), q_type, question, answer, answer_kind(칩/입력) | INTERVENTION 1:1..3 |
| REVIEW | review_id PK, attempt_id FK, answer(만족/후회), answered_at | ATTEMPT 1:0..1 |
| MONTHLY_REPORT | report_id PK, user_id FK, month, interventions, prevented, prevented_sum, mind_change_rate, late_count, regret_rate | USER 1:N |

마음 돌림 비율 = outcome이 방지인 INTERVENTION 수 ÷ 전체 INTERVENTION 수.

## 기술 리스크 · 해결

| 문제 | 해결 방안 | 상태 |
|---|---|---|
| 쿠폰 적용 전·후 금액을 따로 읽어 개입이 여러 번 뜸 | 결제 버튼 위 투명 가드, 버튼을 누른 순간의 최종 금액으로 한 번만 판단 | 해결(프로토타입에서 발견) |
| 간편결제가 버튼 한 번에 진행될 위험 | 가드가 터치를 먼저 받음. 개입 없으면 터치 전달(ACTION_CLICK), 개입 뒤엔 사용자가 다시 누름 | 해결, 실기기 검증 중 |
| 앱마다 결제 화면 구조가 다르고 업데이트로 바뀜 | 공통 신호 파서 + 앱별 규칙, 화면 기록 로그로 보정 | 12주 보정 |
| AI 지연·실패, 호출 비용 | 2초 초과 시 키워드 판정·기본 질문, 가벼움은 AI 호출 없음, 판정 캐시 | 설계 반영 |
| API 키 노출, 개인정보, 프롬프트 인젝션 | 키는 서버에만, 상품명·금액·답만 데이터 필드로, 화면 원문 저장 안 함 | 설계 반영 |
| 테스트 중 실제 결제, Android 13 제한된 설정 | 비행기 모드 테스트 절차, 데모 결제 화면, 온보딩 권한 안내 | 절차 마련 |
| 개입 피로도 | 하루 개입 횟수 리포트, k값 조정 | 14주 측정 |
